# Lab 05: Incident Response Tabletop and Breach Notification Analysis

**Time:** 2-3 hours | **Frameworks:** NIST SP 800-61, ISO 27001 A.5.24-A.5.28, HIPAA Breach Notification Rule, GDPR Art. 33-34, SEC rules

## Scenario
At 09:10 on a Monday, the security team finds that an engineer's cloud access key was exposed in a public code repository. Logs show it was used from an unknown IP address 3 days ago to download a storage bucket containing records of **12,000 patients, including 800 EU residents**. Northwind is a US-based private company serving the US and EU.

## Tasks
1. **Triage:** classify severity and name who must be notified internally.
2. **Contain and preserve:** list the first five actions (revoke key, preserve logs, snapshot evidence, and so on).
3. **Determine legal obligations:** which regimes apply (HIPAA, GDPR, state breach laws, contracts)? Build a notification timeline with deadlines counted from discovery.
4. **Draft** a regulator notification outline and an internal executive update.
5. **Lessons learned:** identify root cause, control failures, and corrective actions (CAPA).
6. Add the new risks and actions to your register.

## Deliverables
Incident timeline, notification matrix, and a post-incident review.

## Self-check
- When does the notification clock start under each regime?
- Who decides legal conclusions (legal counsel, not the GRC analyst)?
- Did you preserve evidence before remediation?
